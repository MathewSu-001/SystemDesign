# 005：加入 CDN Edge Cache

## 狀態

已採用。

## 問題

Stage 04 使用 Shared Application Cache 降低 Database 查詢，但圖片、CSS、JavaScript 等靜態內容仍需進入 Origin Load Balancer 與 Web Server。大量 Client 重複下載相同內容時，Origin 會承擔不必要的網路與處理負載。

## 改動

- 保留 Load Balancer、三台 Web Servers、Shared Application Cache 與 Database Replication。
- 在 Browser 與 Origin Load Balancer 之間加入一個 CDN Edge Server。
- 新增 `/static/logo.txt`，代表可由 CDN 快取的靜態內容。
- `GET /static/*` 使用 CDN Cache；其他 Request 直接 Bypass 至 Origin。
- CDN 保存完整 Origin HTTP Response，並設定三秒 TTL。
- Origin 更新後不主動清除 CDN，刻意展示 CDN 暫時回傳舊內容。

## Request 流程

```text
Static:
Browser -> CDN Edge
           ├-> HIT -> Browser
           └-> MISS/EXPIRED -> Origin Load Balancer
                               -> Web Server
                               -> CDN SET
                               -> Browser

Dynamic:
Browser -> CDN BYPASS -> Origin Load Balancer -> Web Server
                                              -> Shared App Cache
                                              -> Database
```

`BYPASS` 不是額外元件，而是表示 CDN 不使用也不保存這次 Request 的 Cache，直接將 Request 轉送至 Origin。

## CDN 與 Application Cache

| Cache | 直接呼叫者 | 保存內容 | Miss 後來源 |
| --- | --- | --- | --- |
| CDN Edge Cache | Browser | 完整 HTTP Response | Origin |
| Shared Application Cache | Web Server | Database 查詢結果 | Database Replica |

Origin 是 CDN 在 Cache Miss 或 Bypass 時轉送 Request 的上游 HTTP 服務。本階段的 Origin Endpoint 是 Load Balancer，再由它選擇 Web Server；Origin 不等於 Database。

## Cache 規則

```text
GET /static/* -> CDN Cacheable
GET /profile  -> CDN BYPASS
POST /profile -> CDN BYPASS
PUT /profile  -> CDN BYPASS
```

真實 CDN 還會依 HTTP Cache Headers、Query String、Cookie、Authorization 與產品設定決定快取行為。本階段只使用 Method 與 Path，避免同時加入過多規則。

## 驗證順序

1. `POST /profile` 經過 CDN Bypass，初始化動態資料。
2. 第一次 `GET /static/logo.txt` 是 CDN Miss，Origin 回傳 `Logo v1` 並由 CDN 保存。
3. 第二次靜態請求是 CDN Hit，不進入 Load Balancer 或 Web Server。
4. `GET /profile` 經過 CDN Bypass，進入 Stage 04 的 Application Cache 與 Database 流程。
5. 將 Origin 靜態內容更新為 `Logo v2`，CDN 在 TTL 到期前仍回傳 `Logo v1`。
6. TTL 到期後，CDN 重新向 Origin 取得並保存 `Logo v2`。
7. 下一次靜態請求命中 CDN 中的 `Logo v2`。
8. 再次確認動態 `/profile` 不會保存於 CDN。

## Response Headers

- `X-CDN-Cache`：`HIT`、`MISS`、`EXPIRED` 或 `BYPASS`。
- `X-App-Cache`：Application Cache 的 `HIT`、`MISS`、`INVALIDATED` 或 `BYPASS`。
- `X-Data-Source`：CDN Hit 時為 CDN Edge；其餘為 Static Origin、Shared App Cache 或 Database Node。
- `X-Served-By`：實際產生 Origin Response 的 Web Server。

## 啟動程式

